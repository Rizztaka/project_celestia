## Boundary and session evidence limits

The browser reset checks advance an injected service clock while a request waits in the local fixture. They are not live game reset observations or a database-lock simulation. The unchanged PostgreSQL tests cover the actual lock boundary: `routine.integration.test.ts` checks a waiting owner lock at 19:59:59.999→20:00:00.000 UTC; `plan.integration.test.ts` checks both daily and weekly waits, confirms `pg_stat_activity` is waiting on a lock, and rejects the stale command without a revision change. They run in the complete C5 suite, with none skipped.

The delayed write request trace records 2026-10-09T09:22:53.589Z→09:23:23.703Z, HTTP 200; B's login completed at 09:23:00.104Z. The cancelled roster read has no completed-response entry in the finish-only trace; this is not claimed as a successful late HTTP delivery. The actual-client cancellation/session tests cover a delivered old response independently.

Initial browser selector attempts occasionally used copy that did not match the UI; fresh DOM inspection resolved them. Assertions/evidence above use the resulting confirmed state. Interruptions stopped temporary services; failed reads on resume were recovered after the owned services restarted. No production target was substituted.

## Visual and accessibility observations

Fresh pre-change captures: [1440 desktop](before-today-desktop.png), [390 mobile](before-today-mobile.png). Final captures: [1440×1000 desktop](after-today-desktop.png), [390×844 mobile](after-today-mobile.png). Additional inspected views include [inventory](inventory-mobile.png), [320-pixel settings](settings-320.png) and [keyboard choices](keyboard-choices.png). These are C5 captures, not reused C4 images.

- All six primary/supporting pages and all four secondary entries at width 320 had equal document client/scroll widths (305 with scrollbar; NIKKE 320). The encoded equipment page at 390 also had equal 375/375 widths. Each loaded page had one main and one h1. Endgame initially lost focus when its loading main was replaced; keeping a stable outer main fixed it and was rechecked at 1440.
- At 390, measured visible Today buttons, summaries, selects, text/number inputs and checkbox labels had at least 44 CSS pixels of height and width. Checkbox targets use their labels. Inline prose links are not claimed to be 44-pixel buttons.
- Keyboard Enter followed navigation and opened native disclosures. Tab reached the routine checkbox. Escape closed Other tools and returned focus to its summary, with the visible pale-indigo outline. Clicking outside closed it. Skip to content focused the sole main; settings links opened/scrolled their existing controls. Query-only search preserved input focus.
- [Rendered style evidence](rendered-style-check.json) records actual computed colors and the shipped reduced-motion media rule. Muted text was raised to `#a1a1aa`; compared with `#18181b` its contrast is approximately 6.9:1. Header text and active navigation colors also exceed 4.5:1. This is a sampled palette check, not an exhaustive WCAG audit or screenshot pixel test of every translucent background.
- No infinite animations were active in the tested Today screen. The shipped reduced-motion rule disables animations/transitions and hover movement throughout the companion shell. OS preference was **not reduced** during the check. The available browser capability exposes viewport resizing, but no motion emulation; applying Ctrl+Equal did not change viewport or device pixel ratio. Ctrl+0 was sent, and the viewport override was reset. Thus 320-pixel reflow passed, while actual 200%/400% browser zoom and behavior under the OS reduced-motion preference need a human/browser check before invitation. Screen-reader and every legacy tool modal workflow were not audited.

Functional local acceptance passed for the exercised scenarios. Accessibility acceptance is qualified by those explicit limitations. No participant, human timing, feedback, production restore or deployed-state result is inferred.
