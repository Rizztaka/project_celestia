## Persistence and exact public contracts

New shared genshin/plan.ts exports PlanPreferences, PlanSnapshot, PlanAdvice, PlanCommand and strict planCommandSchema. GET /companion/plan?contractVersion=1 returns contractVersion, revision, serverNow, routineRevision, serverId, period, preferences, active goals with current dismissals, enabled routine cards and weekly summary. GET /companion/plan/advice?contractVersion=1 returns plan revision, goal revisions, routine revision, snapshot time/period, full MaterialAdviceResponse, per-goal stock attribution and grouped feasible paid claims. PATCH /companion/plan returns the full PlanSnapshot atomically.

Every PATCH carries contractVersion 1 and expectedRevision. preferences replaces enabledRoutineKinds (unique supported values) and dailyResinBudget (null or integer 0..200). dismissal carries expectedRoutineRevision, serverId, dailyPeriodId, weeklyPeriodId, source (goal ID plus expected goal revision, or stable routine kind), scope day/week and dismissed boolean. Foreign goal IDs return 404. Invalid contracts return 400; stale revision/server/period/goal returns 409; unavailable period returns 400. No retries.

One GenshinPlanPreferences row per User: revision, nullable daily budget, four opt-in booleans. Missing row = revision 0, null budget and no optional kinds, in memory only. A second table holds at most one dismissal per owner/source/scope; upsert replaces its period, goal revision and server. False restores delete the addressed row but advance the durable preferences revision (no ABA). Goal ownership is enforced by a compound FK, unique owner/source/scope and XOR/source-shape checks; supported values, integer bounds and nonnegative revisions also have SQL constraints. Existing tables/rows receive no backfill; only an additive goal ownership index is required. New additive migration; no historical edits.

Dismissals are visibility only. Goals may be dismissed for day or week; routine kinds for their documented display period (commissions/Teapot day, Transformer/weekly claims week). Identity is owner, stable source and supported server period, plus goal revision. Every goal edit/priority/lifecycle change invalidates the old goal dismissal; imports preserve it. Server selection changes explicitly clear owned dismissals and advance an existing plan revision in the same owner-locked C2a write. Disabling a routine hides it without deleting C2a records. Expired rows are ignored on GET and overwritten by subsequent explicit dismissal writes; no growing per-period log and no read cleanup.

The budget is a recurring daily ceiling, not a resin checkpoint or spending ledger. Null is unset; zero is a valid no-spending preference. It persists across reset. Allocation never assumes future regeneration or spending already recorded automatically. The UI states that recording a session does not consume the ceiling.

## Ordering and accounting

Goals: active only for candidates, explicit priority ASC, createdAt ASC, ID ASC. There are no verified deadlines; no fake deadline or availability weights are introduced. Duplicate/malformed goals remain visible with reasons but are excluded from demand. Shortlist defaults to three, with explicit expand/view-all; hidden shortlist entries remain in full demand. Focus cannot exclude intent.

Routines appear in their own fixed section, commissions then Teapot then Transformer; weekly claims in the weekly summary. All optional kinds default off with visible opt-in controls. Completed daily tasks show recorded status, never create drops. No remaining enabled work is a calm state; unavailable clock/stock/routes is distinct.

Aggregate eligible costs over the complete active set, including dismissed goals, then subtract each known inventory quantity once. Reuse C2b stock receipts and null deficits; include Mora and label partial coverage. Attribute stock in stable goal order, including dismissed goals; sum of known attributed deficits equals the aggregate deficit. Unknown stock stays null and cannot prove covered/required work.

For selected undismissed demand, only independently verified open routes with positive integer Original Resin cost per reward claim and matching material keys qualify. Group compatible sources once, reject contradictory shared-source metadata, assign each material to the first eligible source, and allocate integer claims in priority/source order from min(explicit budget, known current estimated resin). A highest-priority source can use all fitting claims; no historical score, per-goal cap, yields or completion date. Unknown need permits route information only, never funded required claims. Counts describe an optional feasible session, not required runs or guaranteed loot; covered stock never completes a goal. Current production routes are empty; positive allocation tests inject explicitly synthetic verified provider facts only.

## Concurrency and SELECT-only reads

Writes use the existing stable owner-row lock (including first writes); sample time after lock and reads; validate all applicable revisions/periods; construct response within the transaction so projection failure rolls back. Source goal ownership/state is checked inside the lock. Every accepted plan write increments one revision.

PlanRepository obtains preferences, dismissals, goals and routine row in one parameterized SELECT. Supporting advice brackets the provider's single coherent stock/receipt SELECT with two plan-context SELECTs and compares complete monotonic intent/routine/preferences state. If it changes, repeat once; persistent churn returns 409. This establishes a common stock-read instant without transaction-control queries on GET. Imports cannot mix stock and receipt. Home panels are independent observations and never combine separate cached stock/resin/goal payloads into allocation. Supporting advice is shown only when its revisions/period match displayed plan state. GET never inserts, locks, resets or prunes.
