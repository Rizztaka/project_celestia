# **Project Celestia UI \& UX Guidelines**

**Document Version:** 1.0

**Status:** Active

**Last Updated:** July 2026

\---

## **Purpose**

This document defines the visual identity, user experience principles, and interface standards for Project Celestia.

Every screen, component, interaction, and animation should follow these guidelines to ensure a consistent experience across the platform.

\---

## **Design Philosophy**

Project Celestia is designed around one simple idea:

«Complex analysis should feel simple to understand.»

Players should never feel overwhelmed by the amount of information available.

Instead, the interface should organize complexity into clear, meaningful, and actionable insights.

\---

## **Design Values**

Every screen should feel:

- Clean
- Modern
- Fast
- Professional
- Intelligent
- Calm
- Consistent
- Accessible

The interface should inspire confidence rather than confusion.

\---

## **User Experience Principles**

Every page should answer three questions within a few seconds:

1\. Where am I?

2\. What can I do here?

3\. What should I do next?

If a page fails to answer these questions, it should be redesigned.

\---

## **Information Hierarchy**

Information should always be displayed in this order:

1\. Most important recommendation

2\. Supporting explanation

3\. Detailed analysis

4\. Advanced information

5\. Raw statistics

Important actions should never be hidden beneath unnecessary details.

\---

## **Dashboard Philosophy**

The dashboard is the heart of Project Celestia.

It should immediately answer:

- What should I do today?
- What changed since yesterday?
- What deserves my attention?
- What is my current progress?

The dashboard should always feel alive and personalized.

\---

## **Navigation Principles**

Navigation should be:

- Predictable
- Consistent
- Minimal
- Easy to learn

Users should never wonder where a feature is located.

Major features should always be accessible within a few clicks.

\---

## **Visual Consistency**

Every page should use:

- Consistent spacing
- Consistent typography
- Consistent iconography
- Consistent button styles
- Consistent cards
- Consistent colors
- Consistent interaction patterns

A component should behave the same way everywhere it appears.

\---

## **Color Philosophy**

Colors should communicate meaning.

Recommended meanings:

- Green → Success
- Blue → Information
- Yellow → Warning
- Red → Error
- Purple → Premium or advanced features
- Gray → Secondary information

Avoid using color as the only way to communicate important information.

\---

## **Typography**

Typography should establish a clear hierarchy.

Use:

- Large headings for sections.
- Medium headings for groups.
- Regular text for explanations.
- Small text for supporting details.

Avoid excessive font variations.

\---

## **Cards**

Cards are the primary content container.

Every card should have:

- A clear title.
- A primary action or insight.
- Supporting information.
- Consistent spacing.

Cards should never become cluttered.

\---

## **Tables**

Tables should prioritize readability.

Features:

- Sorting
- Filtering
- Search
- Responsive layout
- Sticky headers when appropriate

Large datasets should never feel overwhelming.

\---

## **Forms**

Forms should:

- Minimize required input.
- Validate immediately when appropriate.
- Clearly explain errors.
- Preserve entered information after validation failures.

Never make users repeat unnecessary work.

\---

## **Search**

Search should be available wherever users may need to locate:

- Characters
- Weapons
- Artifacts
- Teams
- Materials
- Guides

Search should be fast and forgiving.

\---

## **Empty States**

Empty screens should always explain:

- Why nothing is shown.
- What the user should do next.

Whenever possible, provide a clear action.

Example:

Import your account to begin receiving personalized recommendations.

\---

## **Loading States**

Loading indicators should communicate progress without distracting the user.

Skeleton loaders are preferred over generic spinning indicators for content-heavy pages.

\---

## **Error States**

Errors should:

- Explain what happened.
- Explain what the user can do.
- Avoid technical jargon.
- Preserve user input whenever possible.

\---

## **Accessibility**

Project Celestia should be usable by as many players as possible.

Requirements:

- Keyboard navigation.
- Sufficient color contrast.
- Screen reader compatibility where practical.
- Clear focus indicators.
- Large enough interactive elements.

Accessibility is a core feature, not an afterthought.

\---

## **Mobile Experience**

Mobile support is required.

The interface should adapt naturally to smaller screens without removing important functionality.

Desktop and mobile should provide equivalent capabilities.

\---

## **Animations**

Animations should:

- Feel smooth.
- Be subtle.
- Support understanding.
- Never delay users unnecessarily.

Animation exists to improve clarity, not to show off.

\---

## **Recommendation Presentation**

Every recommendation should include:

- The recommendation itself.
- A short explanation.
- Supporting data.
- Confidence level (where applicable).
- Suggested next action.

Users should understand not only what to do, but why.

\---

## **AI Interaction**

AI-generated explanations should:

- Be concise.
- Be factual.
- Distinguish facts from assumptions.
- Reference the player's own account whenever possible.
- Avoid unnecessary repetition.

The AI should feel like an expert guide, not a chatbot.

\---

## **Performance Experience**

The interface should feel responsive.

Whenever an operation takes noticeable time:

- Show progress.
- Explain what is happening.
- Avoid freezing the interface.

Users should always feel that the application is working.

\---

## **Consistency Rule**

If a new component does not match existing patterns, prefer adapting the new component instead of introducing a new design language.

Consistency is more valuable than novelty.

\---

## **Guiding Principle**

Every screen should help the player answer:

«"What is the best next step for my account?"»

If a screen cannot answer that question, it should be reconsidered.

\---

## **Final Design Principle**

Project Celestia should never impress users through visual complexity.

It should impress them through clarity, usefulness, and trust.
