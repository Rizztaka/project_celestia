## Result and production limits

Home `/` is now Today: a stable three-goal shortlist with expansion, exact goal/character links, persistent opt-in routine kinds, a nullable recurring daily resin ceiling, reversible day/week dismissal, existing manual session/checkpoint recording, current-week reward claims and an independent material advice panel. Priority, pause/resume and explicit completion reuse GoalManager. Other modules and existing Planner tabs/deep links remain reachable. New owners can record routines and create manual goals before import.

No optional routine or budget is assumed. Unknown resin, stock and weekly claims stay distinct from zero. Confirmed routine reminders can show a calm recorded/set-aside state; unavailable farming facts never mean completed work. Recording a routine does not grant materials, spend resin, advance a goal or certify equipment progress. Re-import is the explicit inventory operation.

Full active eligible demand includes collapsed and dismissed goals, preserves Mora and partial coverage, and subtracts recorded stock once before stable attribution. The shared pure projection is also used by the existing Materials consumer. Source groups use known positive needs, verified open routes and whole paid claims within `min(daily ceiling, known estimated resin)`, with no hidden score/run cap/yield forecast. Unknown-only needs retain route information without funded claims. Details are in [the API/state contract](../../api/today-plan.md).

**Production is still deliberately bounded:** verified costs cover only HuTao normal/skill/burst base talent 1–6. No production farming route is verified; all route allocation remains unavailable and zero. Events, live deadlines, weekly discounts and Transformer cooldown estimates remain unavailable. Positive allocation tests use an explicitly synthetic injected provider (including nonconventional resin costs); they establish no new game evidence. No catalog research or data promotion occurred.

## Implementation and review findings

The pre-code [implementation plan](implementation_plan.md) recorded routes, shared DTOs, schema/lifetime, ordering/accounting, owner-lock/clock policy, consistency and UI/test states. C4 extends the existing companion domain with PlanService/PlanRepository and a pure composition helper, not another intelligence engine or scheduler. The additive `20261005150000_add_today_plan_choices` migration introduces minimal user preferences and bounded dismissal rows with neutral defaults, database bounds and compound ownership. It neither backfills nor rewrites earlier intent/routine/import data.

Plan writes use the existing owner lock, expected versions, time sampled after acquiring the lock, current period validation and an atomic response. Any goal revision change makes an older dismissal obsolete; imports preserve choices. Server selection changes explicitly retire owned dismissals and advance existing plan revisions atomically. GETs remain SELECT-only, including first use and rollover; advice brackets coherent stock/receipt reads with unchanged intent snapshots and retries once before 409 on continued churn.

The client pins the originating token and session generation, cancels reads before mutations, rejects old revisions, and invalidates all intent consumers. No blind mutation retry or offline replay is enabled. Failed/conflicting saves and deliberate refresh retain typed drafts and confirmed values. Dispatch checks the server period again using monotonic elapsed time. Independent routine/advice failures do not make the entire home unavailable.

Focused inherited review rechecked C3b ownership, replay, successor/duplicate/malformed semantics, active consumers, re-import continuity and session guards. The legacy priority-only editor and explicit fixed-slot limitations remained correct; no C3b lifecycle repair was needed. Its [historical review](../c3b-focus-goals/implementation_review.md) has a dated appended follow-up.

Two concrete receipt/projection corrections were found during C4 validation:

1. PostgreSQL JSON omits the zone on Prisma's UTC timestamp-without-time-zone columns. New plan date projection initially parsed those values as host-local time. It now marks them as UTC, preserving exact goal times, manual resin and reset periods.
2. Reused material and character/equipment JSON receipt queries had the same inherited shift. They now select `importedAt AT TIME ZONE 'UTC'`. A real PostgreSQL regression compares exact stored ISO timestamps across Materials, plan advice and all three equipment section receipts. Before the equipment fix, `2026-10-05T00:15:30.123Z` incorrectly became `2026-10-04T18:45:30.123Z` on the Asia/Calcutta host; the new assertion failed, then passed after the one-line SQL correction. Browser receipt time changed from the erroneous 09:21:17 to the correct 14:51:17, matching Today for the same synthetic import. Stored data was never rewritten.

Initial focused validation also exposed a fixture insert missing `updatedAt`; the fixture was corrected. The first full run after implementation found one old routine HTTP mock missing the new server-change cleanup delegates; its transaction mock was updated without weakening assertions. A dispatch-time expiry regression was added after the client check moved into the actual mutation path. Final results below include all corrections.
